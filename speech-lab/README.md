# 端末内の音声認識 試作（speech-lab）

車ナビ試作の本体とは別のページです。本体（`../index.html` など）は使いません。

- アドレス：https://hideki0629-star.github.io/car-navi-prototype/speech-lab/
- 状態：試作（Claude Code 作成、2026-10-30）。レビュー前。Owner未承認。

## 目的

iPhoneのSafariの標準の音声認識（Web Speech API）が不安定なため、代わりの候補として、
端末の中だけで動く音声認識（sherpa-onnx の WebAssembly 版）が iPhone で使えるかを確かめる。

## 条件と、その守り方

| 条件 | 守り方 |
|---|---|
| 外部のAPIやサービスを使わない | 部品もモデルも、このページと同じ場所（`sherpa/`）から読み込む。CDNも使わない |
| 音声を端末の外に送らない | 認識はブラウザの中（WebAssembly）で行う。ページに Content-Security-Policy（`connect-src 'self'`）を入れ、自分の公開ページ以外とは通信できないようにしている |
| 日本語に対応 | 日本語専用の音声認識モデル（ReazonSpeech）を使う |
| iPhoneのSafariで動く | WebAssembly の SIMD が必要（iOS 16.4 以降の見込み）。実機で確かめる |

## 使っているもの

| もの | 版 | ライセンス | 大きさ |
|---|---|---|---|
| sherpa-onnx（WebAssembly版、VAD＋音声認識）| 1.12.0（`sherpa-onnx-wasm-simd-1.12.0-vad-asr-ja-zipformer_reazonspeech`）| Apache-2.0（`licenses/sherpa-onnx-LICENSE.txt`）| 本体 wasm 11.5 MB |
| 音声認識モデル reazonspeech-k2-v2（Zipformer、文字単位のRNN-T、約1.6億パラメータ）| sherpa-onnx の配布物に同梱 | Apache-2.0（Hugging Face の reazon-research/reazonspeech-k2-v2 のモデルカードによる）| モデル 171.0 MB（`.data`、VAD を含む）|
| 音声区間の検出 silero-vad | sherpa-onnx の配布物に同梱 | MIT（`licenses/silero-vad-LICENSE.txt`）| 上のモデルに含む |

合計のダウンロード量は 182.5 MB。モデル（`.data`）は GitHub の1ファイル100 MBの上限を超えるため、
2つに分けて置き（`sherpa/*.data.part1`・`part2`）、ページで1つに戻して sherpa-onnx に渡している。
分け方と大きさ・SHA-256 は `sherpa/manifest.json` にある。2回目からはブラウザのキャッシュ（Cache Storage）から読む（保存できた場合）。

## 読み上げについて

今回は作っていない（Owner判断、2026-10-30）。

- sherpa-onnx の読み上げには、日本語に対応したモデルが無い（Kokoro は「英語と中国語だけに対応」と公式に書かれている。Piper の公式の声にも日本語が無い）。
- 日本語に対応する軽い候補として piper-plus（MIT）と声のモデル「つくよみちゃん」（38 MB、FP16）を調べた。
  ただし声のモデルを公開ページに置くことは、つくよみちゃんコーパスの利用条件で「第三者が声質を利用できるようにする行為」にあたり、
  クレジット表示と、出力した音声の使い道を制限する規約（無ければ事前の相談）が必要になるため、見送った。
- piper-plus の日本語の辞書入りの部品（G2P の WebAssembly）は約 60 MB ある。

## 聞き取りの流れ

1. 「聞き取りの試験」を押すと、その押下の中でマイクを求める（iPhoneでは操作の外ではマイクを使い始められないため）。
2. 初回だけ、モデルを読み込む（大きさ・かかった時間を記録に出す）。
3. 音声区間の検出（silero-vad）が、話し始めと話し終わり（0.5秒の無音）を見つける。
4. 話し終わったら、その区間を音声認識にかけて、文字を表示する。一回認識できたら止まる。
5. 「話し終わってから文字になるまで」＝ 話し終わりの判定待ち（0.5秒）＋ 認識の計算の時間 を表示する。

区間の前後に余白（前 0.8秒・後 0.3秒）を足して認識している。VAD が切り出した区間をそのまま渡すと、
言葉の頭を取りこぼした（パソコンでの試験で「福岡駅までナビして」が「また」「駅までナビして」になった）。

アドレスの末尾に `?raw=1` を付けると、ブラウザによる音の加工（エコー除去・雑音抑制・音量の自動調整）を切って比べられる。

## パソコンでの試験（Claude Code、2026-10-30、Edge・画面なし）

Windows の読み上げ（Haruka）で作った「福岡駅までナビして」の音声を、マイクの代わりに流して試した。

| 項目 | 結果 |
|---|---|
| ダウンロード | 182.5 MB、手元のサーバーから約1秒 |
| WebAssembly の初期化 | 0.24秒 |
| 音声区間の検出の準備 | 0.89秒 |
| 音声認識モデルの準備 | 4.5〜5.1秒 |
| 認識の結果 | 「福岡駅までナビして」（余白を足したあと。加工あり・`?raw=1` とも）|
| 話し終わってから文字になるまで | 約1.07秒（判定待ち 0.50秒 ＋ 計算 0.57秒）|

## iPhoneで確かめること

| 項目 | 結果 |
|---|---|
| ページが開けるか。記録の SIMD が「あり」か | |
| 182.5 MB の読み込みが最後まで終わるか。かかった時間 | |
| モデルの準備の途中で、ページが落ちないか（メモリ不足でSafariが再読み込みしないか）| |
| マイクの許可が出て、「声を検出」が出るか | |
| 「福岡駅までナビして」などが正しく文字になるか | |
| 話し終わってから文字になるまでの時間 | |
| 2回目に開いたとき、キャッシュから読めるか（記録に「キャッシュから」と出るか）| |
| `?raw=1` を付けたときと比べて、聞き取りが良くなるか | |
