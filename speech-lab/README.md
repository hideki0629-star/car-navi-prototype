# 端末内の音声 試作（speech-lab）

車ナビ試作の本体とは別のページです。本体（`../index.html` など）は使いません。

- アドレス：https://hideki0629-star.github.io/car-navi-prototype/speech-lab/
- 状態：試作（Claude Code 作成、2026-10-30）。レビュー前。Owner未承認。

## 目的

iPhoneのSafariの標準の音声認識（Web Speech API）が不安定なため、代わりの候補として、
端末の中だけで動く聞き取り（sherpa-onnx の WebAssembly 版）と読み上げ（piper-plus）が iPhone で使えるかを確かめる。

## 条件と、その守り方

| 条件 | 守り方 |
|---|---|
| 外部のAPIやサービスを使わない | 部品もモデルも、このページと同じ場所から読み込む。CDNも使わない。読み上げの声のモデルは、端末に保存したファイルを選んで使う |
| 音声を端末の外に送らない | 計算はすべてブラウザの中（WebAssembly）で行う。ページに Content-Security-Policy（`connect-src 'self'`）を入れ、自分の公開ページ以外とは通信できないようにしている。インラインのスクリプトは import map（ハッシュで指定）だけを許している |
| 日本語に対応 | 聞き取りは日本語専用のモデル（ReazonSpeech）、読み上げは日本語に対応した piper-plus と声のモデル（つくよみちゃん）|
| iPhoneのSafariで動く | WebAssembly の SIMD が必要（iOS 16.4 以降の見込み）。実機で確かめる |

## 聞き取り（ストリーミング表示）

- 画面側（`lab.js`）がマイクの音を 16000 Hz にして、約85ミリ秒ごとに Web Worker（`asr-worker.js`）へ流し込む。
- Worker で音声区間の検出（silero-vad）と音声認識（reazonspeech-k2-v2）を行う。計算を Worker に分けているので、計算の間もマイクの取り込みは止まらない。
- **ストリーミングについて**：sherpa-onnx には、日本語のストリーミング用モデル（話しながら少しずつ認識するモデル）と、その WebAssembly 版が無い（日本語は話し終わってから認識する方式のモデルだけ）。
  そこで、話している間は「話し始めから今まで」の音を約0.4秒ごとに認識し直して、途中の文字を出している（計算が遅ければ間隔を自動で広げる）。
  話し終わったら（0.5秒の無音）、区間全体を認識して最終の文字にする。本物のストリーミングより計算が多く、話が長いほど途中の文字の計算が重くなる。
- 表示する時間：
  - 話し終わってから最終の文字が確定するまで ＝ 話し終わりの判定待ち（0.5秒）＋ 処理の待ち ＋ 最終の認識の計算
  - 声を検出してから最初の途中の文字が出るまで、途中の文字の回数
- 区間の前後に余白（前 0.8秒・後 0.3秒）を足して認識している。VAD が切り出した区間をそのまま渡すと、言葉の頭を取りこぼした（「福岡駅までナビして」が「また」「駅までナビして」になった）。
- アドレスの末尾に `?raw=1` を付けると、ブラウザによる音の加工（エコー除去・雑音抑制・音量の自動調整）を切って比べられる。

## 読み上げ

- 「読み上げの試験」を押すと「福岡駅まで案内します。」と読み上げる。
- 記録に「読み上げ開始：音を出し始めました」「読み上げ終了：音を出し終わりました」を出す。音が聞こえたかは人が確かめる。
  作った音の大きさ（最大・平均）も出すので、音が聞こえないとき、声が作れていないのか（ほぼ無音）、再生されていないのかを見分けられる。
- iPhoneのSafari（16.4以降）では、読み上げの前に音の使い方を「playback」にして、マナーモードでも鳴るようにしている（聞き取り中は変えない）。
- **声のモデルは公開しない**（試験用、Owner指示 2026-10-30）。このリポジトリには置いていない。
  端末に保存した2つのファイルを「声のモデルを選ぶ」で選ぶと、その端末のブラウザの中（IndexedDB）にだけ保存され、次からは選び直さなくてよい。
  - `tsukuyomi-chan-6lang-fp16.onnx`（39.7 MB）
  - `config.json`（6.9 KB）
  - 配布元：Hugging Face の ayousanz/piper-plus-tsukuyomi-chan（ファイルを端末に保存するのは利用者の操作。このページは配布元と通信しない）
  - ライセンス：つくよみちゃんコーパス（CV.夢前黎）の利用規約に従う。合成した音声を外部に公開しない使い方であれば制限は無い、とされている。
- piper-plus は声のモデルを「http(s) のアドレス」で受け取るため、ページの中で仮のアドレス（`local-tts-model/tsukuyomi.onnx`）を作り、
  そのアドレスへの読み込みだけを、ブラウザ内に保存したファイルにつなぎかえている（外部へは出ない）。

## 使っているもの

| もの | 版 | ライセンス | ダウンロード量 |
|---|---|---|---|
| sherpa-onnx（WebAssembly版、VAD＋音声認識）| 1.12.0（`sherpa-onnx-wasm-simd-1.12.0-vad-asr-ja-zipformer_reazonspeech`）| Apache-2.0（`licenses/sherpa-onnx-LICENSE.txt`）| 本体 wasm 11.5 MB |
| 音声認識モデル reazonspeech-k2-v2 | 上に同梱 | Apache-2.0（Hugging Face の reazon-research/reazonspeech-k2-v2 のモデルカードによる）| 171.0 MB（`.data`、VAD を含む）|
| 音声区間の検出 silero-vad | 上に同梱 | MIT（`licenses/silero-vad-LICENSE.txt`）| 上に含む |
| piper-plus（読み上げ）| 0.8.2（npm）| MIT（`vendor/piper-plus/LICENSE.md`、`THIRD-PARTY-LICENSES.md`）| 日本語の辞書入りの G2P wasm 60.1 MB ＋ JS |
| @piper-plus/g2p | 0.4.2（npm）| MIT（`vendor/piper-plus-g2p/LICENSE.md`）| 小さい |
| onnxruntime-web | 1.30.0（npm）| MIT（`licenses/onnxruntime-LICENSE.txt`）| wasm 14.2 MB |
| 声のモデル つくよみちゃん | `tsukuyomi-chan-6lang-fp16.onnx` | つくよみちゃんコーパスの利用規約 | このページには置かない（端末のファイルから 39.7 MB）|

- 聞き取りは合計 182.5 MB。モデル（`.data`）は GitHub の1ファイル100 MBの上限を超えるため、2つに分けて置き（`sherpa/*.data.part1`・`part2`）、
  Worker で1つに戻して sherpa-onnx に渡している。分け方と大きさ・SHA-256 は `sherpa/manifest.json`。2回目からはブラウザのキャッシュ（Cache Storage）から読む（保存できた場合）。
- 読み上げは約75 MB（G2P wasm 60.1 MB ＋ onnxruntime wasm 14.2 MB ＋ JS）。ブラウザの通常のキャッシュに任せている。
- `vendor/` のファイルは npm の配布物をそのまま置いている（書き換えていない）。

## パソコンでの試験（Claude Code、2026-10-30、Edge・画面なし）

Windows の読み上げ（Haruka）で作った「福岡駅までナビして」の音声を、マイクの代わりに流して試した。
声のモデルは手元の作業用フォルダからだけ読ませた（リポジトリには入れていない）。

| 項目 | 結果 |
|---|---|
| 聞き取りの読み込み | 182.5 MB、手元のサーバーから約1秒。準備完了まで合計 7.6秒（音声認識モデルの準備 5.3秒）|
| 途中の文字 | 2回（「福岡駅まで延べ」→「福岡駅までナビして」）。声を検出してから最初の途中の文字まで 約0.8秒 |
| 最終の文字 | 「福岡駅までナビして」 |
| 話し終わってから最終の文字が確定するまで | 約0.93秒（判定待ち 0.50秒 ＋ 待ち 0.07秒 ＋ 計算 0.37秒）|
| 読み上げの準備 | 4.4秒（onnxruntime 14.2 MB、G2P 60.1 MB、声のモデル 39.7 MB）|
| 声を作る時間 | 0.4〜0.6秒（音の長さ 1.9秒、音の大きさ 最大 0.36）|
| 読み上げの開始・終了 | 記録に出た（画面なしのため、音は耳では確かめていない）|
